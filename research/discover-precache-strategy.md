## 한 줄 요약

> **Discover는 토픽이 고정(bounded)이므로 "전부 미리 캐싱"이 정답이고 최우선이다.** 지금은 방문할 때마다 SearXNG를 라이브로 때려 느리고 차단 위험이 있다. **cron 백그라운드 갱신 → 캐시 저장 → 페이지는 캐시만 읽기** 구조로 바꾼다. 일반 검색창 쿼리는 미리 캐싱하지 않고 lazy fill로 둔다.

---

## 왜 Discover만 "전부 미리 캐싱"이 안전한가

- Discover는 **노출할 토픽이 고정·유한**하다 → 사용자가 0명이어도 "뭘 보여줄지" 이미 정해져 있어 예측 불가 문제가 없다.
- 따라서 "전부 캐싱"이 **색인 함정이 아니다.** (집합이 작고 고정이라 비용 상한이 명확.)
- 반대로 **일반 검색창**은 쿼리가 무한·예측 불가 → 미리 못 채운다. 첫 요청이 채우는 lazy fill(cache-aside)이 정석.

| 대상 | 미리 캐시? | 이유 |
|---|---|---|
| Discover (고정 토픽) | ✅ 전부 미리 (최우선) | 집합이 고정·유한 → 예측 가능 |
| 일반 검색창 쿼리 | ❌ lazy fill | 무한·예측 불가 → 첫 요청이 채움 |

## 현재 구현 상태 (As-Is)

파일: `src/app/api/discover/route.ts`

- 토픽 9개 하드코딩: `korea`, `tech-kr`, `finance-kr`, `entertainment-kr`, `sports-kr` (한국) + `tech`, `finance`, `art`, `sports`, `entertainment` (영어).
- 각 토픽마다 쿼리 배열이 하드코딩되어 `naver news` / `bing news` 엔진으로 검색.
- **문제 1 — 캐시 없음:** `GET` 핸들러가 **매 방문마다** `searchSearxng`를 라이브 호출(`Promise.all`로 여러 쿼리 동시). 느리고, 트래픽이 늘면 네이버/빙에 차단당할 위험.
- **문제 2 — 비결정적:** `.sort(() => Math.random() - 0.5)`로 매 호출 셔플 → 캐싱과 충돌(매번 다른 순서).
- **범위:** 검색 결과 카드(제목·요약·썸네일=스니펫)만. 본문 fetch도, LLM 요약도 없음.

## 목표 구조 (To-Be)

```
[cron, 예: 10~30분마다]
  9개 토픽 쿼리를 SearXNG에 돌려 → 결과 정규화·dedup → 캐시에 저장
        │
[유저가 /discover 방문]
  └─ GET /api/discover → 캐시에서 즉시 읽음 (SearXNG 호출 0, 즉답)
        └─ 캐시 미스/만료 시에만 라이브 폴백 + 즉시 캐시에 채움
```

- **외부 호출 상한 고정:** 토픽 수 × (쿼리 수) × (1 / 갱신주기). 방문자 수와 무관 → 무료 서비스에 안전.
- **페이지 지연:** 캐시 읽기 = ms 단위. 라이브 SearXNG 왕복 제거.

## 설계 디테일

### 1. 캐시 저장소 선택
- **Redis 권장** (이미 떠 있음): 키 `discover:{topic}:{lang}`, 값 = 정규화된 카드 배열(JSON).
- TTL은 cron 주기보다 약간 길게(예: cron 15분 → TTL 30~60분)로 두어, cron이 실패해도 직전 결과를 계속 서빙(= stale-while-revalidate 효과).
- 영속성이 필요하면 Postgres 테이블 병행(컨테이너 재시작 대비).

### 2. 갱신 메커니즘 (cron)
- 별도 워커/스케줄러에서 주기적으로 모든 토픽을 갱신해 캐시에 write.
- 토픽별로 순차/소량 병렬 → 네이버·빙에 버스트 부하 주지 않기.
- **셔플은 캐시 read 시점에 적용**(저장은 결정적 순서로). 즉 `Math.random()` 셔플을 route 응답 단계로 옮긴다.

### 3. 신선도 vs 비용
- 뉴스성 토픽(`korea`, `*-kr` 뉴스)은 신선도가 중요 → 짧은 주기(10~15분).
- 비뉴스/안정적 토픽은 긴 주기 허용(30~60분).
- 주기는 환경변수로 토픽군별 조절 가능하게.

### 4. 스탬피드/콜드 방지
- 캐시 미스 시 동시 다발 라이브 호출 방지 → **singleflight(요청 합치기)** 또는 토픽별 락.
- 최초 배포 직후엔 cron 1회를 즉시 실행해 캐시를 시드(빈 Discover 노출 방지).

## 경계 (하지 말 것)

- ❌ 일반 검색창 쿼리까지 미리 캐싱 시도 (= 색인 함정).
- ❌ Discover 워머가 결과 페이지의 **링크를 따라가며 재귀 수집** (= bounded → unbounded 전락).
- ✅ 입구를 "고정 토픽(또는 트렌드 리스트 상위 N)"으로 고정해 항상 bounded 유지.
