# 구글 공식 API vs 직접 스크래핑 — PoC & 전략 재검토

> 측정일: 2026-07-01
> 대상: https://search.vsvs.kr (OCI 도쿄, 운영과 동일 IP) — 구글 직접 스크래핑 fan-out 재현 + 공식 API 조사
> 관련: [04-naver-scraper-blocking-poc.md](./04-naver-scraper-blocking-poc.md) · [05-naver-api-vs-scraping.md](./05-naver-api-vs-scraping.md) · [06-engine-inventory.md](./06-engine-inventory.md)

## TL;DR

> **"커뮤니티를 구글 `site:`로 옮기면 된다"는 이전 가정(05·06 문서)은 이 PoC로 뒤집혔다.** 구글은 네이버보다 **훨씬 공격적**이다 — 순차 단일 요청도 간헐 403, 8동시 fan-out은 **첫 질의부터 과반 차단**, 그리고 한번 걸리면 **12분 동안 회복 안 됨**(네이버는 ~3분 자동회복). 게다가 차단이 **IP 전체에 걸려** PoC 직후 운영의 `google`·`fmkorea`·`startpage` 엔진이 전부 `Suspended: CAPTCHA`로 다운됐다. **구글 공식 API도 무료 100건/일(신규 가입 중단·2027 종료)로 답이 안 된다.** → 커뮤니티는 "구글 경유"가 아니라 **네이버 저동시성 스크래핑+캐시 또는 유료 SERP API(Serper.dev)** 로 가야 한다.

## 1. PoC 결과 — 구글 스크래핑 차단 (fmkorea 요청 방식 복제)

시나리오: 커뮤니티 8개를 구글로 옮기면 "사용자 검색 1회 = 구글에 8개 `site:` 동시 요청"이 된다. 그 fan-out을 그대로 재현.

### Part A — 순차 단일 요청 (구글이 gentle엔 관대한가?)

```
[1] 403  [2] 403  [3] 200  [4] 200  [5] 403
```

→ **순차 단일도 5번 중 3번 403.** (네이버는 순차 20/20 전부 통과였음 → 구글이 훨씬 빡셈)

### Part B — 마이그레이션 fan-out 재현: 검색1회=8동시, 10회 반복

```
user#1: 차단 4/8   ← 첫 질의부터 과반 차단
user#2: 차단 5/8
user#3: 차단 8/8   ← 전멸
user#4: 7/8   user#5: 8/8   user#6: 4/8   user#7: 6/8
user#8: 6/8   user#9: 7/8   user#10: 6/8
```

→ 전부 HTTP **403**(일부 429). **네이버는 질의 2번째에 트립**됐지만, **구글은 질의 1번째부터 과반 차단.**

### Part C — 회복 폴링 (60초 간격, 12분)

```
+60s 403 / +120s 403 / +181s 403 / +241s 403 / +302s 429 /
+362s 403 / ... / +725s 403   → 12분 내 회복 안 됨
```

→ **네이버 ~3분 자동회복 vs 구글 12분+ 미회복.** (403/429 혼재)

### 운영 영향 (IP 전체 차단 확인)

PoC 직후 SearXNG 상태:

```
google      : Suspended: CAPTCHA
fmkorea     : Suspended: CAPTCHA   ← 우리의 유일한 커뮤니티 엔진 다운
startpage   : Suspended: CAPTCHA   (구글 백엔드)
duckduckgo  : CAPTCHA
brave       : too many requests
```

→ 구글 차단은 **IP 단위**라 구글 계열 엔진이 **연쇄 다운**. SearXNG는 CAPTCHA → `SearxEngineCaptcha` = **명목 24시간 정지**([04](./04-naver-scraper-blocking-poc.md)의 suspend 표).

### 네이버 vs 구글 스크래핑 직접 비교

| 항목               | 네이버            | 구글                             |
| ------------------ | ----------------- | -------------------------------- |
| 순차 단일 요청     | ✅ 20/20 통과     | ❌ 5중 3 403                     |
| 8동시 fan-out 트립 | 질의 **2번째**    | 질의 **1번째**(과반)             |
| 응답 코드          | 403 access denied | **403/429 + CAPTCHA**            |
| 회복 시간          | **~3분 자동회복** | **12분+ 미회복**                 |
| 차단 범위          | 네이버 엔진만     | **IP 전체(구글 계열 연쇄 다운)** |
| 결론               | 나쁨              | **더 나쁨**                      |

> ⚠️ 단서: OCI IP는 이미 fmkorea가 구글을 스크래핑 중이라 **사전 플래그** 상태였을 수 있고, 데이터센터 IP는 본질적으로 불리. 그래도 방향성은 명확 — **구글은 동시 site: fan-out을 강하게·오래 차단.**

## 2. 구글 공식 API 조사 — 네이버 같은 관대한 무료 API가 없다

|           | 네이버 오픈 API | 구글 공식 옵션                                                                   |
| --------- | --------------- | -------------------------------------------------------------------------------- |
| 무료 쿼터 | **25,000/일**   | **100/일** (250배 적음)                                                          |
| 유료      | —               | Custom Search **$5/1,000**, 하루 **최대 10,000** 하드캡                          |
| 결과 한도 | 콜당 100        | 콜당 10, **총 100건**                                                            |
| 상태      | 정상            | ⚠️ **신규 가입 중단 + 무료 전체웹 검색 2027.1.1 종료**, 신규 PSE는 50도메인 제한 |

- **Custom Search JSON API / PSE:** 무료 100/일뿐, 신규 고객엔 닫히는 중, 무료 전체웹 검색 2027.1 종료. → 무료 서비스가 커뮤니티 검색을 감당할 규모 아님.
- **Vertex AI Search:** ~$1.50/1,000 + 최소 약정(1,000 QPM+50GB) → 무료 소비자 서비스엔 과함.
- **현실적 대안 = 3rd-party SERP API:**

| 제공자            | 무료         | 유료(~1k당)    |
| ----------------- | ------------ | -------------- |
| **Serper.dev** ⭐ | 2,500 크레딧 | **$0.30~1.00** |
| Bright Data       | 5k/월        | ~$1.50 (PAYG)  |
| SerpApi           | 100/월       | ~$15           |

## 3. 전략 재검토 — 05·06 문서의 "커뮤니티 → 구글 경유" 정정

이전 문서들은 "네이버 자산=API, **커뮤니티=구글 `site:`**"를 권했지만, **이 PoC로 구글 경유가 오히려 더 나쁜 것으로 확인**됐다(fmkorea가 지금까지 버틴 건 질의당 **구글 요청 1개**였기 때문 — 8개로 늘리는 순간 붕괴).

### 커뮤니티 수집 대안 (재정렬)

| 방안                                   | 장점                          | 단점                                 | 비용     |
| -------------------------------------- | ----------------------------- | ------------------------------------ | -------- |
| **A. 네이버 스크래핑 + 저동시성/캐시** | 이미 구현됨, 커버리지 좋음    | 네이버 차단(단, ~3분 회복·완화 가능) | $0       |
| **B. Serper.dev(구글 SERP 유료)** ⭐   | 차단 없음, 안정, `site:` 지원 | 유료(~$0.3/1k), 외부 의존            | ~$0.3/1k |
| C. 네이버 카페 API                     | 정식·무료(카페 한정)          | 카페 외 커뮤니티 불가                | $0       |
| D. 각 커뮤니티 직접 스크래핑           | 검색엔진 우회                 | 사이트별 안티봇 각개대응             | $0       |

### 핵심 결론

- **구글 직접 스크래핑으로의 커뮤니티 이전은 기각.** (더 강하고 긴 차단 + IP 전체 연쇄 + 공식 API도 부재)
- **네이버 자산 = 네이버 공식 API**(25k/일)로 가는 결정은 유효([05](./05-naver-api-vs-scraping.md)).
- **커뮤니티는** ① 네이버 스크래핑을 **동시성 캡+캐시로 길들이거나**(무료, [04] 처방), ② 규모/안정이 필요하면 **Serper.dev 유료**로. 어느 쪽이든 "구글 직접 스크래핑 fan-out"은 피한다.
- **공통 원칙 재확인:** 문제의 본질은 "네이버냐 구글이냐"가 아니라 **"한 검색을 한 곳에 동시 다발로 때리는 fan-out"**. 목적지를 구글로 바꿔도 fan-out이면 똑같이(더 심하게) 막힌다. → **동시성 억제 + 캐시가 진짜 해법.**
